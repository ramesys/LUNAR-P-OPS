# LUNAR-OPS Sprint 01

This extension preserves the upstream CLPS browser and its MIT license. It supports one candidate at a time in the Sample A terrain view. Sample A is a placeholder, not an official landing site.

Start with `docker compose up --build` (the first run downloads NASA kernels and terrain). If the upstream data service times out, retry it; its downloaded files are retained in `data/`. To use the already downloaded Sample A windows and kernels without waiting for the optional other terrain windows and basemap, build with `docker compose build api web` and start with `docker compose up -d --no-deps api web`. Open http://localhost:5180, run the comparison, focus Sample A, expand its 3D view, and click the surface. Drag to orbit; scroll to zoom. Select the time and observer height before clicking: the candidate records a snapshot. A later click replaces C0.

The mesh is an approximately 93.75 m sampled display grid, with lunar curvature and optional vertical exaggeration; neither its height nor its exaggeration is used as the candidate elevation. The API maps the click's local east/north coordinates through the existing south-polar stereographic convention and bilinearly samples the 20 m LOLA near-field grid. Coordinates are planetocentric latitude and east longitude in [0, 360), in the upstream documented MOON_ME (DE421) convention; elevation is metres above the 1737.4 km sphere. Requests outside the displayed ±6 km patch, outside grid coverage, or on missing values are rejected. A click is limited by mesh discretization and floating-point raycasting, not survey precision.

`site_id` identifies the geographical coordinate; `candidate_id` hashes a canonical JSON representation of position, observer height, UTC time, dataset source, resolution, sampled elevation and coordinate convention. It is an input identity, not a claim of physical uniqueness or validation. The source URL and sample resolution are returned separately. The dataset is downloaded externally and not version-pinned by checksum; a changed upstream DEM may change the result and ID. Data availability means only that the required sample was obtained. It does not establish scientific accuracy, navigation suitability, terrain clearance, or landing safety. Independent validation is outstanding.

The standard suites are `make test`; with Docker running and data downloaded, `docker compose run --rm --no-deps -T -v ./backend:/workspace api pytest -q` and `docker compose run --rm --no-deps -T web pnpm -r --workspace-root test` run the two parts. The real-LOLA test is skipped when Sample A's window is absent. Upstream data and licenses remain attributed in the root README and LICENSE.
