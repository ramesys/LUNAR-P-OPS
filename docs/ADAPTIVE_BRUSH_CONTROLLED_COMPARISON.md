# Adaptive Region Brush: controlled comparison (work in progress)

These are deterministic synthetic fields, **not LOLA/SPICE observations or validation**. Run from `backend/` with `python -m api.tests.adaptive_comparison`. The field implementation and complete coordinate sequences are printed as JSON. The tests check equal attempt budgets, reproducibility, and a changed adaptive sequence when the field changes.

Each experiment uses the same square, availability rule, feasibility thresholds (both synthetic visibility values ≥ 0.5) and nine attempted locations. Uniform sampling uses a 3×3 grid with spacing 2; adaptive sampling chooses from a 5×5 lattice with spacing 1. Both have access to the same synthetic field; no observer or time variation is modeled. Synthetic “simultaneous” is **min(Sun, Earth)**, a proxy, not physical simultaneous visibility. The obstructed case marks the center unavailable for both methods. The harness supplies Sun and Earth values and their constraint margin to the selector; it does not model horizon clearance, darkness, or temporal transitions. Attempts count against the budget even when unavailable. Timings measure only Python selection and synthetic lookup, not terrain, horizons, or SPICE.

Boundary pairs are a descriptive proximity count, not a reconstructed boundary; the non-dominated count is not a measure of distance between Pareto solutions. Coverage is mean distance across all 25 lattice positions to the nearest attempted point, including unavailable attempts; lower is better. A single run took roughly 0.04–0.06 ms for uniform lookup and 0.1–0.2 ms for adaptive selection on this machine; these microbenchmarks are noisy and exclude scientific computation. Results depend on these constructed fields, grid alignment, and the choice of seed policy; they do not establish that adaptive sampling is generally better.

The earlier real-data run had exactly nine eligible points and a budget of nine, so both methods exhausted the same set. A further real-data smoke test used a 1.6 km square, the same nine-attempt budget, 168 hours at six-hour steps, a 0.5 simultaneous-visibility threshold, and the same observer settings: the uniform grid used 800 m spacing and adaptive used a 200 m lattice. All nine results in both modes were `COMPUTED_UNVERIFIED`, with zero simultaneous fraction and FAIL verdicts. Both chose the same nine coarse-grid locations; the verdict and simultaneous-visibility evidence used by that earlier prototype was identical, so its exploration fallback selected those locations. This is a bounded observation, not proof of performance or coverage elsewhere.

After adding separate visibility/gap metrics, constraint margins, sampled horizon proximity and a bounded temporal step, the same real-data setup gave a different sequence. The initial point (800, 800) had Sun-visible fraction 3/28, while (-800, 800) had 0/28; both had Earth and simultaneous fractions zero. The policy chose (0, 800) next, citing the Sun/gap difference between those parent evaluations. It later selected (-200, 800), (0, -200), and (200, 800), then spent its ninth attempt on a three-hour-step computation between two six-hour samples at (800, 800). The eight full-window adaptive results and all nine uniform results failed the 0.5 simultaneous threshold. The temporal result is a shorter interval and has no full-window verdict. Uniform used 252 location-time samples; adaptive used 226, so this is an equal **attempt** budget, not an equal number of full-window spatial evaluations. A single warm-cache run took approximately 2.21 s and 1.17 s respectively; ordering and cache effects prevent a performance conclusion.

The Region Brush retains completed adaptive snapshots under content-addressed IDs and can reload them; an interruption before completion may leave candidate/evaluation records without a completed experiment snapshot. The graph displays selected-candidate lineage alongside its C0/C1 dataflow. Timeline comparison reports exact UTC matches only. The temporal policy refines at most one first observed transition within the original interval, using a reserved final attempt; it does not interpolate or assess full-window constraints on that short interval. Caches are bounded and process-local. These results are `COMPUTED_UNVERIFIED`; do not treat the comparisons as independent scientific validation.

One local, warm-filesystem profile at the ROI center used 24 hourly samples: loading both DEM grids took 0.033 s, explicit ray-coverage verification 0.042 s, and the horizon-mask call 0.041 s; the full first evaluation took 0.207 s and an identical in-process repeat 0.020 s, with the same evaluation ID. These are individual measurements with overlapping responsibilities, not additive components or a portable benchmark. Cache hits check the current terrain and kernel content keys; a new physical evaluation still performs the existing ray coverage validation.
